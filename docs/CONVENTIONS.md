# PnC Core Suite — Build Conventions (binding contract)

BillingCoreAJ2026 (`BIL`, BillingCenter parity) and ClaimsCoreAJ2026 (`CLM`,
ClaimCenter parity) are synthetic COBOL / CICS TS / Db2 for z/OS applications
that sit beside IBM GenApp (policy admin). Everything here is binding: programs
that break these rules are rejected by review even if they compile.

## 1. Program styles

| Style | Where | Entry | Calls others with | Unit of work |
|---|---|---|---|---|
| **A. Dual-mode service** | `src/common`, `src/online` (business engines) | `LINKAGE SECTION. 01 DFHCOMMAREA.` + `PROCEDURE DIVISION USING DFHCOMMAREA.` ends with `GOBACK` | `CALL WS-xxx-PGM USING WS-xxx-CA` (dynamic CALL, program name in a WS field) | Never COMMIT/ROLLBACK; the caller owns it |
| **B. CICS front end** | `src/online` (3270 screens, `*P` suffix) | pseudo-conversational, `EXEC CICS RETURN TRANSID COMMAREA` | `EXEC CICS LINK PROGRAM(...) COMMAREA(...) LENGTH(4000) RESP(WS-RESP)` | CICS syncpoint at task end; `EXEC CICS SYNCPOINT ROLLBACK` on service RC >= 90 |
| **C. Batch driver** | `src/batch` | JCL `EXEC PGM=IKJEFT01` (DSN RUN) | `CALL` style-A services; files via `SELECT/FD` | `EXEC SQL COMMIT` every `WS-COMMIT-FREQ` rows (default 200) and at end; restart key in a checkpoint file |

Style A programs contain **no `EXEC CICS`** — that is what lets batch reuse them.
Only style B contains `EXEC CICS`.

## 2. COMMAREA contract

Every style A service takes exactly 4000 bytes: `<APP>CAHDR` (160) + a body
copybook (3840). Lengths are verified by `tools/calen.py`; never change a
contract copybook without re-running it.

Service side:
```cobol
       LINKAGE SECTION.
       01  DFHCOMMAREA.
           COPY BILCAHDR.
           03 CA-BODY.
              COPY BILCACT.
```
Caller side (unique tag per callee so names never collide):
```cobol
       01  WS-ACT-CA.
           COPY BILCAHDR REPLACING LEADING ==CA-== BY ==ACA-==.
           03 ACA-BODY.
              COPY BILCACT REPLACING LEADING ==CA-== BY ==ACA-==.
       01  WS-ACT-PGM                  PIC X(8) VALUE 'BILACCT0'.
           ...
           INITIALIZE WS-ACT-CA
           MOVE 'ACCTINQ'          TO ACA-REQUEST-ID
           MOVE CA-USER-ID         TO ACA-USER-ID
           MOVE CA-BUS-DATE        TO ACA-BUS-DATE
           MOVE WS-PROGRAM-ID      TO ACA-CALLER-PGM
           CALL WS-ACT-PGM USING WS-ACT-CA
           IF NOT ACA-RC-OK ...
```
Return codes (88s in the header): 00 ok, 04 warning, 08 not found,
12 validation, 16 conflict/duplicate/optimistic-lock, 20 authority exceeded,
24 invalid state transition, 90 Db2 error, 91 CICS error, 98 bad length,
99 unknown request id. Always set `CA-REASON-CODE` (8 chars, e.g. `ACTNOTFD`)
and a human `CA-MESSAGE` on any non-zero RC. Propagate a callee's RC >= 12
upward unchanged with its reason code.

## 3. Program anatomy

* Fixed format, columns 8–72 only, upper case, no tabs, no sequence numbers.
* Header comment block (copy the exemplar `BILSEQGN`): program, application,
  function, request ids, called by, calls, tables with CRUD letters, business
  rules list, change log (`2026-10-27 AJ  Initial version`).
* Paragraph numbering: `0000-MAINLINE`, `1000-INITIALISE`, `2nnn-` request
  handlers, `3nnn-` validation, `4nnn-` Db2 access, `5nnn-` calculations,
  `8nnn-` calls to other services, `9000-RETURN`, `9900-DB2-ERROR`.
  `PERFORM ... THRU ...-EXIT` is allowed but not required; be consistent.
* `01 WS-PROGRAM-ID PIC X(8) VALUE '<pgm>'.` in every program.
* **Business rules are tagged** where implemented:
  `      * BR-BIL-PAY-004 Oldest past-due item is paid first`. IDs are
  `BR-<APP>-<MODULE3>-<nnn>`; list them in the header block too. This is what
  rule-extraction tooling keys on, so tag real decisions only.
* No dead code, no commented-out code, no filler paragraphs written to inflate
  line counts. Size comes from real behaviour: validation, state machines,
  calculations, error handling, audit, cursors.

## 4. Db2

* `EXEC SQL INCLUDE SQLCA END-EXEC` and the DCLGEN members (`BILDxxx`,
  `CLMDxxx`, `GENDxxx`) — never hand-declare a table's host variables.
  DCLGENs are generated by `tools/dclgen.py` from `ddl/`. Field names are
  `<PFX>-<COLUMN>`; VARCHARs are `<fld>-LEN` + `<fld>-TEXT`.
* Qualify tables: `BILDB.BIL_ACCOUNT`, `CLMDB.CLM_CLAIM`, `GENAPP.POLICY`.
  ClaimsCore reads GenApp tables; nobody writes them.
* SQLCODE handling after every statement:
  `0` ok · `+100` not found (RC 08 or end of cursor) · `-803` duplicate
  (RC 16) · `-911/-913` deadlock/timeout (RC 90, reason `DEADLOCK`) ·
  anything else RC 90 and `CALL 'BILERRLG'` (or `CLMERRLG`) with program,
  paragraph, SQLCODE, key.
* Optimistic locking on tables with `VERSION_NO`:
  `UPDATE ... SET VERSION_NO = VERSION_NO + 1 ... WHERE KEY = :k AND
  VERSION_NO = :v`; `SQLERRD(3) = 0` → RC 16 reason `STALEVER`.
* Surrogate keys come from `BILSEQGN`/`CLMSEQGN` (`SEQNEXT`), never MAX()+1.
  Sequence names are the table's DCLGEN prefix (`ACT`, `PPR`, `CLM`, ...),
  business numbers use `ACTNO` (account number), `INVNO`, `CLMNO`, `CHKNO`.
* Timestamps: `CURRENT TIMESTAMP` in SQL. Business date: `CA-BUS-DATE`; when
  spaces, read `<APP>_CONTROL` row `'SYSTEM  '`.
* Null indicators: use the DCLGEN `IND...` structure for nullable columns
  on SELECT; on INSERT/UPDATE set the indicator to -1 for null.
* Cursors: `DECLARE ... CURSOR [WITH HOLD] FOR ... FOR FETCH ONLY` in
  WORKING-STORAGE; always CLOSE on every exit path.

## 5. Money, dates, numbers

* Money is `PIC S9(11)V99 COMP-3` in WORKING-STORAGE/COMMAREA,
  `DECIMAL(13,2)` in Db2. Use `ROUNDED` on every COMPUTE that divides or
  multiplies by a rate. Splits and rates go through `BILMONEY`/`CLMMONEY`.
* Dates are ISO `yyyy-mm-dd` (`PIC X(10)`). Arithmetic goes through
  `BILDATES`/`CLMDATES` (style A, `CALL`), never hand-rolled.
* Currency is GBP; rates are basis points (`RATE_BPS`, 1250 = 12.50%).

## 6. Cross-application integration

All integration is asynchronous through the event queues
(`BIL_EVENT_QUEUE`, `CLM_EVENT_QUEUE`) via `BILEVTQ`/`CLMEVTQ`, drained by
batch `BILEVTDR`/`CLMEVTDR`. Event types and payloads (fixed-position text in
`PAYLOAD`) are defined in `docs/EVENTS.md`. GenApp policy events reach billing
as `POLISSUE`, `POLCHNG`, `POLCANC`; claims payments reach billing as
`CLMPAYMT`; billing tells claims the billing status via `BILSTAT`.

## 7. Validation (definition of done for every program)

```
python3 tools/validate.py billing billing/src/common/BILSEQGN.cbl
```
must print PASS. `validate.py` stands in for the CICS and Db2 precompilers
(EXEC blocks become CONTINUE / comments, EXEC SQL INCLUDE becomes COPY) and
runs `cobc -fsyntax-only -std=ibm`. A program is done when it passes, follows
this document, and every request id in its contract copybook is implemented.
